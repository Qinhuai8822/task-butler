# Mode: plan-grill · 计划压测

适用场景：重要方案执行前的系统性拷问——新产品方案、架构决策、
重大采购、对外发布内容、任何不可逆或高成本的决定。
非重要任务不要用（会拖慢节奏）。

## 流程

1. 把方案映射成**设计树**：每个决策节点上挂着依赖它的子决策。
2. 每轮只问"前沿问题"——前置决策已明确、现在就能答的问题。
   一轮内把前沿问题全部编号列出，每题附上你的推荐答案，然后等用户回答。
3. 用户的回答重塑整棵树：已定的决策把前沿向外推，解锁下游问题；
   依赖未决问题的问题留到下一轮，不要抢跑。
4. 收口标准：前沿为空——所有分支都有结论，没有任何默默的假设。
   此时向用户复述一遍"我们的共同理解"，确认后才进入执行。

## 规则

- **事实自己查**：任何能从环境里查到的事实（文件、数据、文档），
  自己去查或派子任务查，不问用户；查询中的问题不阻塞本轮其他提问。
- **决策才问用户**：选择题、取舍、偏好，交给用户，并给出推荐答案。
- 推荐答案的措辞让用户"答是"即等于采纳推荐。
- 用户答"都行 / 你定"时，采用推荐答案并在下一轮开头声明。
